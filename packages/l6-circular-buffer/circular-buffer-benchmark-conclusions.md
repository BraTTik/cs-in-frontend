# Circular Buffer Benchmark: выводы

## Что измеряли

Бенчмарк в `packages/l6-circular-buffer/index.ts` измеряет методы:

- `push`
- `pop`
- `shift`
- `unshift`

Для размеров буфера: `10`, `100`, `1_000`, `10_000`, `100_000`.

Перед замерами выполняется прогрев JIT.

## Что показывают результаты

1. `total` время (`*TotalMs`) растет с увеличением размера.
  Это ожидаемо, потому что на каждом размере выполняется количество операций, равное размеру (`operations = size`).
   Следовательно, измеряется стоимость *пакета из N операций*, а не одной операции.
2. Среднее время одной операции (`*AvgNs`) остается в одном порядке величин (десятки наносекунд, с флуктуациями).
  Это соответствует ожидаемой асимптотике `O(1)` для операций кольцевого буфера.
3. `unshift` в среднем чаще медленнее остальных.
  Вероятная причина: дополнительная работа с индексом начала (`#zero`) и связанные ветвления/арифметика индексов.
4. Значения `avg/op` не строго монотонны и могут "плавать" между размерами.
  Это нормально для микробенчмарков в JS/Node из-за влияния:
  - JIT tiering и деоптимизаций,
  - CPU cache и branch prediction,
  - шума планировщика ОС,
  - точности таймера на очень коротких участках.

## Практический итог

- Реализация подтверждает ожидаемое поведение для кольцевого буфера: операции не требуют перераспределения памяти и сдвига элементов.
- По текущим замерам архитектурная цель `O(1)` для `push/pop/shift/unshift` соблюдается на уровне `avg/op`.
- Рост `total` с размером не противоречит `O(1)` и объясняется ростом числа выполненных операций.
