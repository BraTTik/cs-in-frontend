# Benchmark Results: CSV (`parseCsv`) vs JSON

## Условия прогона

- CSV: **200000** строк данных; потоковый разбор через `parseCsv("./data.csv", ...)` (см. `index.ts`)
- JSON: **200000** объектов в массиве; `fs.readFileSync` + `JSON.parse` для `json.json`
- Память: `process.memoryUsage()` после завершения соответствующего этапа

## Результаты

### CSV

| Метрика | Значение |
|--------|----------|
| First read (timeLog) | `3.892ms` |
| Полное время (timeEnd) | `267.436ms` |

**CSV Parse Memory**

- HeapTotal: `17.88MB`
- HeapUsed: `11.67MB`
- RSS: `75.20MB`

### JSON

| Метрика | Значение |
|--------|----------|
| Время парсинга (timeEnd) | `315.517ms` |

**JSON Parse Memory**

- HeapTotal: `106.03MB`
- HeapUsed: `85.45MB`
- RSS: `213.50MB`

## Интерпретация

- По времени полного прогона CSV (`267.436ms`) быстрее JSON (`315.517ms`) примерно на **~15%** в этом прогоне.
- Память после CSV существенно ниже: HeapUsed **11.67MB** против **85.45MB**, RSS **75.20MB** против **213.50MB** — JSON держит весь документ в строке и в распарсенном объекте, CSV в этом сценарии нагружает кучу заметно слабее.
