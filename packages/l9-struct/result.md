# Результаты `bench.ts` (ImageData 1920×1080)

Замеры в миллисекундах (`set`, `read`, `fill`, `saveTime`, `readTime`), размеры файлов — как в `formatSize` (КБ, строка).

## Сводка по прогону


| Блок       | set | read | fill | type            | saveTime | readTime | size     | gz      | br      |
| ---------- | --- | ---- | ---- | --------------- | -------- | -------- | -------- | ------- | ------- |
| **Binary** | 0.09 | 0.01 | 30.02 | Binary          | 19.48    | 2.70     | 8100.00 KB  | 7.91 KB  | 0.03 KB |
| **Flat**   | 0.08 | 0.02 | 56.04 | Array JSON      | 603.90   | 278.15   | 32400.03 KB | 31.57 KB | 0.11 KB |
| **Arrays** | 0.00 | 0.00 | 168.52 | Array of Arrays | 846.67   | 1014.74  | 36450.03 KB | 88.49 KB | 0.13 KB |


*(Строки `Binary` / `Flat` / `Arrays` в консоли — это три сравнения: мутации через `Matrix2D` + сериализация binary; мутации через `FlatPixelStream` + JSON «плоский» массив; мутации через `ArraysPixelStream` + JSON «массив массивов».)*

## Выводы

### 1. Мутации в памяти (`set` / `read` / `fill`)

- `set` и `read` остаются субмиллисекундными во всех трёх вариантах; это очень короткие операции, где абсолютные различия малы и чувствительны к шуму окружения.
- `fill` показывает устойчивое преимущество `Binary` (`Matrix2D`): **~30.02 ms** против **~56.04 ms** (Flat) и **~168.52 ms** (Arrays).
- По полной заливке матрица на сыром буфере выигрывает у Flat примерно в **1.9x**, у Arrays — примерно в **5.6x**.

### 2. Сериализация на диск (`saveTime` / `readTime` / `size`)

- **Бинарный формат** — лидер по I/O: запись **~19.48 ms**, чтение **~2.70 ms**, размер **8100.00 KB**.
- **Array JSON (плоский массив)**: запись **~603.90 ms**, чтение **~278.15 ms**, размер **32400.03 KB**.
- **Array of Arrays** — самый тяжёлый вариант: запись **~846.67 ms**, чтение **~1014.74 ms**, размер **36450.03 KB**.

**Итог:** для хранения/обмена растровым кадром этого же размера бинарный формат существенно выигрывает и по времени, и по размеру. JSON оправдан в основном там, где нужна человекочитаемость/совместимость текстового обмена.

### 3. Сжатие (`gz` / `br`)

- После сжатия все форматы уменьшаются на порядки; в этом прогоне: Binary (**7.91 KB gz**, **0.03 KB br**), Flat (**31.57 KB gz**, **0.11 KB br**), Arrays (**88.49 KB gz**, **0.13 KB br**).
- Экстремально малые значения после сжатия указывают на очень высокую сжимаемость текущего датасета (много повторяющихся значений после `fill`), поэтому эти цифры стоит интерпретировать вместе со сценарием генерации данных.
- Для корректного сравнения между прогонами полезно дополнительно логировать размеры в байтах без округления.
